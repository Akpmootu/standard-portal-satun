# ข้อมูลบังคับลงทะเบียน — 19 ตุลาคม 2569

- แยกชื่อและนามสกุลเป็นช่องบังคับ รวมเป็น display_name เดิมก่อนส่ง จำกัดความยาวรวม 100 ตัวอักษร ตำแหน่งบังคับกรอก
- หน่วยงานเลือกจากรหัสหน่วยบริการสตูล 74 รหัสที่ระบบอนุญาตและมีรายการในสารบบจริงเท่านั้น ไม่รับชื่อหน่วยงานพิมพ์เองหรือรหัสนอกจังหวัด API ตรวจทั้ง allowlist และการมีอยู่ของหน่วยบริการก่อนส่งคำขอลงลายมือชื่อ
- คำขอใหม่เก็บรหัสหน่วยงานใน organization เดิม ไม่เปลี่ยน schema หรือให้สิทธิ์ hospital_id อัตโนมัติ หน้าผู้ดูแลแสดงรหัสพร้อมชื่อและเลือกหน่วยบริการที่ร้องขอไว้ให้ตรวจ ก่อนแอดมินตัดสินบทบาท/ขอบเขตจริง
- เบอร์โทรเป็นกล่อง 10 ช่อง บังคับครบทุกหลัก รับแปะเบอร์เต็มและย้ายช่องอัตโนมัติ เซิร์ฟเวอร์รับเฉพาะเลข ASCII 10 หลัก ช่องนี้เป็นหมายเลขติดต่อ ไม่ใช่ระบบส่ง/ยืนยัน OTP
- อีเมลแสดงจาก Google เป็น readonly ไม่มีชื่อ field สำหรับส่งอีเมลจากฟอร์ม API ยังผูกอีเมลจาก session และปฏิเสธ field อีเมลที่ส่งปลอมเพิ่มมา

## ตัวนับผู้ลงทะเบียน

SSR แสดงจำนวนตามหน่วยบริการที่เลือก ปุ่ม “ตรวจจำนวนล่าสุด” เรียก GET /api/registration/units แบบต้องมี session และ no-store อัปเดตจำนวนโดยไม่ล้างข้อมูลในแบบฟอร์ม ไม่แสดงชื่อ/อีเมล/เบอร์ของผู้สมัครอื่น และไม่อนุญาต query เจาะข้อมูลหรือ POST

นับบัญชี Google ไม่ซ้ำที่ยื่นคำขอทุกสถานะ ไม่ใช่จำนวนผู้ได้รับสิทธิ์หรือผู้ใช้งานที่ยัง active ข้อมูลเดิมเทียบได้เฉพาะรหัส ชื่อหน่วยงานที่ตรงกัน หรือหน่วยงานที่เคยมอบหมายไว้ ไม่เดาจากชื่อบุคคล/อีเมล คำขอเก่าที่ระบุหน่วยงานไม่ได้ไม่รวมและมีคำอธิบายในหน้า

## ความเข้ากันได้

ไม่แก้ข้อมูลคำขอเดิมย้อนหลัง ไม่เติมเลขโทรศัพท์หรือเดาหน่วยงานให้ข้อมูลเก่า การสมัครยังต้องรออนุมัติ ไม่เพิ่มบัญชี สิทธิ์ หรือ scope จากข้อมูลที่กรอกเอง

ใช้โครงสร้างคำสั่ง registration เดิม ชุดคำสั่งใหม่ยังผ่าน Writer เดิมในชุดทดสอบ VM ได้ กติกาที่เข้มขึ้นบังคับบนเซิร์ฟเวอร์ Vercel ก่อนลงลายมือชื่อและส่ง Writer ซึ่งผู้สมัครไม่มี signing secret ชุด Writer ที่ build ใหม่เก็บกติกาเดียวกันไว้สำหรับ deploy ในอนาคต ไม่จำเป็นต้องเปลี่ยน schema หรือ deploy Apps Script เพื่อใช้ฟอร์มนี้

## ตรวจแล้ว

- ชุดทดสอบ 190 รายการผ่าน รวม full-name/phone/unit validation, email injection, ไม่ส่งชื่อบุคคลใน counts, ไม่รับรหัสนอกจังหวัด, ไม่รับหน่วยบริการที่ไม่มีในสารบบ, signup–approve–save–review ตามสิทธิ์เดิม
- Chrome บนข้อมูลสมมติ: เลือกหน่วยบริการเห็นผู้สมัคร 1 บัญชี วางเบอร์ 10 หลักได้ เบอร์ 9 หลักส่งไม่ได้ กรอกครบส่งสำเร็จแล้วรออนุมัติ ปุ่มตรวจจำนวนบนอีกหน้าปรับจาก 1 เป็น 2 โดยไม่ reload ฟอร์ม
- อีเมล readOnly และไม่ส่งเป็น field; โทรศัพท์มี 10 ช่อง required; ตรวจ responsive 320/390/768/1025/1440 px ไม่พบล้นแนวนอน
- ไม่สมัครบัญชีจริงหรือเปลี่ยนสิทธิ์จริงเพื่อทดสอบแบบฟอร์ม

ขั้นถัดไป: ตรวจ deployment และรายการหน่วยบริการ production แบบอ่านอย่างเดียว แล้วให้ผู้สมัครใหม่ทดลองตามขั้นตอนจริง
