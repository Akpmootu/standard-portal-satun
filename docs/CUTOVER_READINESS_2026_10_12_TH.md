# ตรวจความพร้อมก่อนย้ายผู้ใช้และปิดระบบเดิม

> เพิ่มผลตรวจรับ CTAM ผ่านเว็บจริงและ Google Sheets พร้อมคืนบทบาทแอดมินแล้ว ดู [CTAM_PILOT_ACCEPTANCE_2026_10_12_TH.md](CTAM_PILOT_ACCEPTANCE_2026_10_12_TH.md) คู่มือทั้งสองฉบับดาวน์โหลดจริงและเทียบ SHA-256 ผ่านแล้ว ข้อความด้านล่างเป็นสถานะก่อนรอบนำร่อง ไม่ใช้ข้อที่ผ่านเพิ่มแล้วเป็นงานค้างซ้ำ

อัปเดต 12 ตุลาคม 2569 เวลา 14:12 น. ไทย สถานะ: **ยังไม่ประกาศสลับระบบหลักและยังไม่ปิดระบบเดิม** ผู้ใช้ยืนยันเป้าหมายให้ย้ายผู้ใช้เข้าระบบใหม่และปิดการใช้งานระบบเดิมหลังตรวจครบ ไม่ต้องย้าย Mistral

ข้อมูลแจ้งเตือนเดิม 179 รายการที่หาเจ้าของผู้ใช้ต้นทางไม่พบ เก็บครบในคลังแอดมินแล้ว ต้องมีบัญชีข้อยกเว้นที่เจ้าของระบบรับทราบก่อนตรวจรับ ไม่เดาชื่อหรือผูกเข้ากล่องข้อความส่วนบุคคล

## สำรองและกู้คืนรอบนี้

- สำรองข้อมูลปัจจุบันเวลา 14:07:54 ไทย: 25 ตารางและไฟล์หลักฐาน 4 รายการ เข้ารหัสและตรวจถอดรหัสผ่าน SHA-256 plaintext `fd421f0b0ae9526050b172ac09900162a4c1bfeddf7c4f5723fc129d53189475` เป็นสำรองในเครื่องรอบใหม่ ไม่ได้อ้างว่าอัปโหลดสำรองรอบนี้แล้ว
- ดาวน์โหลดสำรองคลังต้นทางจาก Drive จริง `1sgqAO0NcNbOxjT0qj2uwSZ8unR36zraJ` ขนาด 12,452,835 bytes ตรวจเป็นส่วนตัวของเจ้าของระบบก่อนดาวน์โหลด
- ถอดรหัสและเขียนกู้คืนลงโฟลเดอร์ใหม่ใต้ `.secrets/archive-restore-*` ซึ่งสืบทอด ACL ส่วนตัว ตรวจอ่านไฟล์กลับครบ 20 ตาราง 45,880 แถว, 5 ไฟล์ และ 6 ตำแหน่งต้นทาง SHA-256 plaintext `68f94e86f749ae6c6bbad6fb45a05bac4eb86b599c361c8246d87e52df5ed52c`
- รอบนี้เป็น **กู้คืนไฟล์จากสำรองบนคลาวด์ลงเครื่องแยก** ยังไม่ใช่การสร้าง Google Sheets/Drive ชุดกู้คืนบนคลาวด์ใหม่ และไม่ได้เปลี่ยนตัวชี้ production
- ต้องมอบกุญแจสำรองให้ผู้รับผิดชอบเก็บแยกจากไฟล์สำรอง พร้อมทดสอบว่าผู้รับผิดชอบกู้ได้จริง กุญแจไม่อยู่ใน GitHub/Drive หรือรายงานนี้

## Telegram และโฮสต์

ยังไม่มีหลักฐานยืนยันรอบอัตโนมัติรายวัน/รายสัปดาห์ สถานะ sent ของรายการรายวัน 08:46:52 ไม่บอกผู้เรียกและอยู่ก่อนเวลา 09:00 การค้น runtime logs รอบเช้าผ่าน CLI ใช้ไม่ได้ (400); ค้นชั่วโมงล่าสุดได้แต่ไม่พบ cron จึงไม่สรุปว่ารอบเช้าล้มเหลวหรือสำเร็จ ต้องตรวจรอบ scheduled จริงพร้อมเวลาเรียกและ audit ที่สัมพันธ์กัน โดยไม่ใช้การกดทดสอบแทน

เอกสาร [Vercel Hobby](https://vercel.com/docs/plans/hobby) ระบุ personal/non-commercial use และเก็บ runtime logs 1 ชั่วโมง จึงไม่รับรองการใช้ระบบหน่วยงานระยะยาวฟรีจากการ deploy สำเร็จ ผู้ใช้เลือก **คง Vercel และรอยืนยันเงื่อนไข** ไม่มีการเปลี่ยนโฮสต์หรืออัปเกรดแผนในรอบนี้ ตาราง Hobby มีความคลาดเคลื่อนของเวลาได้ตาม [ข้อจำกัด Cron](https://vercel.com/docs/cron-jobs/usage-and-pricing)

## ลำดับสลับระบบที่ต้องปฏิบัติ

1. ตรวจรับรายการนำร่องผ่านเว็บจริง: สมัคร → อนุมัติบทบาท → บันทึก/เปิดหลักฐาน → ส่งกลับ → ส่งใหม่ → อนุมัติ → ประวัติ/รายงาน; ตรวจทั้งสามโมดูลตามกติกาและสิทธิ์จริง ไม่สร้างผลผ่านเกณฑ์สมมติในรายงานราชการ และคงรายการ 09611/2569/ข้อ 1.3 ที่อนุมัติแล้ว
2. ปิดประเด็นเงื่อนไขโฮสต์ ตรวจรอบ Telegram จริง และกำหนดผู้ดูแลสำรอง/กุญแจ ยืนยันรายการข้อยกเว้นย้อนหลัง หากยังไม่ผ่านให้หยุดก่อนสลับระบบ
3. บันทึกเวลาหยุดรับข้อมูลเดิมและช่วงตรวจรับ แจ้งผู้ใช้ด้วยข้อความที่เจ้าของระบบอนุมัติ ช่วงนี้ **ห้ามทั้งสองระบบรับเขียนพร้อมกัน**; สำรองระบบใหม่ก่อนกระทบยอด
4. เปิดโหมดพักระบบเดิมที่ขอบเขตเว็บแอปเดิมทั้งหมด รวม URL เขียน/API/export ที่ต้องใช้สิทธิ์ ไม่ใช่แค่ซ่อนปุ่มหรือล็อกหน้า login และพัก cron เดิมเพื่อไม่ส่ง Telegram ซ้ำ ต้องตรวจโครงสร้าง server จริงก่อนเลือกวิธีติดตั้ง ไม่เปลี่ยนสิทธิ์ทั้งเครื่องหรือแอปอื่น
5. ตรวจว่า session เดิมและการเรียก API โดยตรงบันทึกไม่ได้ ขณะพักให้ GET แสดง HTTP 503 พร้อมข้อความย้ายระบบและลิงก์เว็บใหม่; POST/คำขอเขียนต้องถูกปฏิเสธ ห้าม redirect ส่ง payload เก่าไปเว็บใหม่ ต้องคง SSH/การส่งออกแบบอ่านอย่างเดียวสำหรับตรวจรับ
6. ส่งออกต้นทางหลังพักแล้ว เทียบครบ 20 ตารางและไฟล์อีกครั้ง หากมี delta ให้จัดแผนเพิ่ม/แก้ตามรายการ พร้อมตรวจการชนกับรายการในเว็บใหม่ หยุดเมื่อพบความขัดแย้ง ห้าม bulk import ทับทั้งชีต คลังต้นฉบับที่มี modifiedTime lock ต้องเก็บเป็นรุ่นใหม่และตรวจรับก่อนเปลี่ยน catalog
7. สำรองหลังปรับข้อมูลทั้งระบบปัจจุบันและคลังต้นทาง ตรวจผลต่างและการกู้คืนจากสำเนาที่จัดเก็บแยก บันทึก deployment/ตัวชี้/เวลา freeze/ผลตรวจและผู้ตรวจรับ
8. เมื่อทุกข้อผ่าน จึงประกาศเว็บใหม่เป็นแหล่งข้อมูลหลัก ปิดการใช้งานเว็บเก่า โดยเก็บฐานข้อมูล/โค้ด/ไฟล์สำรองส่วนตัวตามระยะเก็บของหน่วยงาน ไม่ลบฐานข้อมูลเดิม ไม่ยกเลิกโฮสต์ทั้งเครื่อง และไม่เผยข้อมูลย้อนหลังเป็นสาธารณะ

## เงื่อนไขย้อนกลับ

หากข้อมูลขาด สิทธิ์ผิด หรือเขียนข้อมูลไม่แน่นอน ให้หยุดเขียนเว็บใหม่และเก็บ snapshot ของรายการที่เพิ่มหลังสลับก่อน ห้ามเปิดรับเขียนเว็บเก่าทันทีจนตรวจ/นำรายการใหม่กลับครบหรือเจ้าของข้อมูลรับรองแผนรายรายการ การ rollback deployment อย่างเดียวไม่ใช่ rollback ข้อมูล ต้องคงบัญชีแผนย้อนกลับที่รวมข้อมูลทั้งสองฝั่งและตรวจยอดก่อนเปิดให้ผู้ใช้เขียนอีกครั้ง

## ขั้นต่อไป

ตรวจวงจรผ่านเว็บจริงและหลักฐานด้วยรายการที่เจ้าของข้อมูลยอมรับ ขณะรอยืนยัน Vercel เตรียมวิธีพักเฉพาะเว็บเดิมจากการตรวจ server จริง แล้วจึงกำหนดเวลา freeze/กระทบยอด/ตรวจรับ/ประกาศสลับ ยังไม่มีการปิดระบบเดิมหรือส่งประกาศให้ผู้ใช้ในรอบนี้
