# ทดสอบเบื้องต้นและกระทบยอดต้นทาง — 12 ตุลาคม 2569

## วงจรข้อมูลสมมติ

เพิ่มการตรวจครบวงจรผ่าน HTTP ของแอปจริง โดยใช้บัญชีสมมติและตัวเก็บข้อมูลในหน่วยความจำแยกจากระบบจริง ไม่มีการโหลดข้อมูลลับ ส่ง Google API หรือ Telegram และไม่มีการเปลี่ยนบทบาทบัญชีจริง

ผ่านขั้นตอนสมัคร → รออนุมัติ → แอดมินกำหนดบทบาทหน่วยบริการ/ผู้ตรวจและขอบเขตปี → บันทึก → ส่งกลับพร้อมข้อเสนอแนะ → ส่งใหม่ → อนุมัติ → ตรวจประวัติสองเหตุการณ์ รายงาน HTML และ CSV

ตรวจเพิ่มเติมว่าการลงทะเบียนยังไม่ให้สิทธิ์, บัญชีหน่วยบริการตรวจอนุมัติเองไม่ได้, ผู้ตรวจบันทึกแทนหน่วยบริการไม่ได้, ผู้ตรวจเปิด CTAM ไม่ได้, การอ่าน/เขียนข้ามหน่วยและนอกปีถูกปฏิเสธ, CSRF ผิดถูกปฏิเสธ, ส่งคำขอเดิมซ้ำไม่เพิ่มข้อมูล, เวอร์ชันเก่าถูกปฏิเสธ, ส่งใหม่คืนสถานะรอตรวจแต่เก็บประวัติ และปิดบัญชีแล้วเซสชันเดิมถูกปฏิเสธทันที ข้อมูลตั้งต้นและข้อมูลนอกสิทธิ์ไม่ได้ถูกเปลี่ยนหรือรั่วไปใน CSV

ผลท้ายรายการสมมติเป็นเวอร์ชัน 4 มีประวัติ 2 เหตุการณ์ และใบรับการบันทึก 4 รายการ ชุดทดสอบรวม 171 รายการผ่าน

เบราว์เซอร์บล็อกการเปิดหน้าทดสอบในเครื่อง (`ERR_BLOCKED_BY_CLIENT`) จึงไม่ได้ถือว่ารอบนี้ตรวจวงจรผ่านหน้าจอแล้ว ไม่ได้ลดการป้องกันเบราว์เซอร์หรือเปลี่ยนไปอ่านหน้าที่บล็อกด้วยเครื่องมืออื่น การตรวจ HTTP ใช้กระบวนการทดสอบโค้ดในสภาพแวดล้อมจำลอง ไม่ใช่การเข้าถึงหน้าที่ถูกบล็อก

## ต้นทางล่าสุด

อ่านข้อมูลธุรกิจจากต้นทางด้วยธุรกรรมอ่านอย่างเดียว ณ 12 ตุลาคม 2569 เวลา 13:48:03 ไทย เทียบครบ 20 ตาราง 45,880 แถวกับชุดที่ตรวจย้ายแล้ว ณ 11:21:03 ทุกค่าตรงกัน รวมโครงสร้าง ชนิดข้อมูล NULL และจำนวนแถวซ้ำ โดยไม่นับลำดับแถวที่ SQL ไม่รับประกันเป็นการเปลี่ยนข้อมูล ไม่ได้ใช้จำนวนแถวเพียงอย่างเดียว

คงการไม่ย้ายคอลัมน์รหัสผ่านเดิมไว้เหมือนรอบแรก ไม่มีการเขียนฐานข้อมูลเดิมหรือชีตปลายทาง การตรวจนี้เทียบต้นทางกับภาพข้อมูลที่เก็บรักษาไว้แล้ว ไม่ใช่การยืนยันว่าหยุดเขียนต้นทางหรือประกาศเว็บใหม่เป็นแหล่งข้อมูลหลัก

## สิ่งที่ยังต้องตรวจรับ

- วงจรผ่านหน้าจอและการเขียน Google Sheets จริงยังแยกจากผลทดสอบสมมติ ต้องเลือกรายการนำร่องที่ยอมรับผลจริงและใช้หลักฐานที่ตรวจเปิดได้ ไม่เพิ่มผลทดสอบลงในรายงานจริง
- Audit พบสรุป Telegram รายวันวันที่ 12 ตุลาคม 2569 เวลา 08:46:52 สถานะส่งสำเร็จ แต่ข้อมูลไม่ได้ระบุว่ามาจากตัวตั้งเวลา จึงยังไม่ถือว่ายืนยันรอบอัตโนมัติ 09:00 น. หรือรายสัปดาห์ได้ รอบนี้ไม่ได้ส่งข้อความใหม่
- ยืนยันผู้ดูแลกุญแจสำรองแยก ตรวจเงื่อนไขโฮสต์/โควตาสำหรับงานหน่วยงาน และยืนยันเจ้าของประวัติแจ้งเตือนเก่าที่ผูกไม่ได้
- ตกลงช่วงหยุดเขียนระบบเดิม กระทบยอดล่าสุดอีกครั้ง สำรองก่อน/หลัง และเตรียมแผนย้อนกลับก่อนประกาศสลับระบบหลัก
