# ขั้นที่ 6 — เตรียมประวัติตรวจ MOU ปี 2569

> เอกสารเตรียมการเก่า: งานนำเข้าเสร็จและตรวจซ้ำแล้ววันที่ 7 กันยายน 2026 **ไม่ต้องรันส่งออกหรือนำเข้าซ้ำ** อ่าน [สถานะปัจจุบัน](MOU_HISTORY_VERIFIED_STEP6_TH.md) แทนขั้นตอนด้านล่าง

สถานะ 4 กันยายน 2026: เตรียมตัวส่งออกและตัวตรวจข้อมูลแล้ว ทดสอบรวม 87 รายการผ่าน พร้อมตรวจ syntax JavaScript/config และ PHP ผ่าน **ยังไม่ได้ส่งออกประวัติจริงหรือเขียนประวัติลง Sheets** หน้าเว็บยังอ่านอย่างเดียว ไม่ต้อง restart เพื่อรัน helper นี้

## สิ่งที่ทำแล้ว

- ส่งออกผ่าน SSH stdin ด้วยบัญชี `administrator` และคีย์เดิม ไม่ติดตั้ง PHP helper ไว้ใน web root ไม่เปิด Billing
- อ่านเฉพาะ `mou_review_history` ที่เชื่อมกับ `mou_progress` ปีงบประมาณ 2569 และ 74 หน่วยบริการในโครงการ ใช้ transaction READ ONLY แล้ว rollback จำกัด 5,000 รายการ
- กรองปีจากผลประเมินแม่ ไม่ใช่ปีปฏิทินของวันที่ตรวจ ประวัติที่ไม่มีผลประเมินแม่ไม่อยู่ในการส่งออกนี้ จึงไม่ใช่การสำรองฐานข้อมูลทั้งหมด
- ตรวจ hash ของ snapshot อ้างอิงและผลประเมินกับใบรับรองการนำเข้าในเครื่อง ก่อนเรียก SSH แล้วตรวจ parent ID/หน่วยบริการ/ตัวชี้วัดก่อนบันทึกไฟล์
- สร้าง ID `legacy-mou-history-…` เชื่อม parent `legacy-mou-…` เก็บวันที่เป็นข้อความเดิม และเก็บชื่อผู้ตรวจเป็น provenance `legacy:…` ไม่ผูกกับบัญชีใหม่หรือเพิ่มสิทธิ์
- หากประวัติใหม่กว่าวันตรวจล่าสุดใน snapshot หรือ parent ไม่มีวันตรวจล่าสุด จะรายงาน `readyForImport: false` เพื่อรอตรวจความต่าง ไม่เขียนทับผลประเมินเดิม
- `readyForImport: true` หมายถึงผ่านตัวตรวจ snapshot เท่านั้น ไม่ใช่อนุญาตให้นำเข้าโดยไม่ตรวจชีตสดหรือรับรองว่าข้อมูล production ไม่เปลี่ยน
- ข้อมูลประวัติตามระบบเดิมเป็น admin-only ยังไม่เพิ่ม endpoint/หน้าดูประวัติ และไม่เปิดเผยชื่อผู้ตรวจย้อนหลังให้ผู้ใช้หน่วยบริการ

จำนวน 95 แถวที่พบใน inventory เก่าไม่ใช่ยอดประวัติปี 2569 ที่ยืนยันแล้ว ต้องใช้ผลส่งออกจริง

## เจ้าของรันครั้งต่อไป

เปิด PowerShell อีกหน้าต่างหนึ่ง โดยปล่อย server พอร์ต 3000 ทำงานต่อ ไม่ต้องหยุดหรือรันซ้ำ จากนั้นคัดลอกเฉพาะคำสั่งต่อไปนี้:

```powershell
Set-Location -LiteralPath 'C:\Users\user\Documents\Codex\2026-09-01\new-chat\work\standard-portal-google'
$portalNode = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe'
$portalKey = Join-Path $env:USERPROFILE '.ssh\id_rsa'
& $portalNode scripts/export-mou-history-local.js administrator $portalKey '.migration/mou-reference-2026-09-04T03-48-11-193Z.json' '.migration/mou-progress-2569-2026-09-04T06-46-27-533Z.json'
```

ตัวช่วยสร้างไฟล์ใหม่แบบไม่ทับไฟล์เก่าใน `.migration` และพิมพ์เฉพาะ path/hash/ยอดรวม ไม่มีชื่อผู้ตรวจ ความคิดเห็น ลิงก์หลักฐาน หรือ credentials ในผลสรุป ส่งกลับเฉพาะผลสรุปใน Terminal **ไม่แนบไฟล์ JSON** และห้ามนำ `.migration`, `.secrets`, `.env*` ขึ้น GitHub หรือแชร์ zip ทั้งโครงการ

ถ้า `readyForImport: false` หรือพบ `MOU_HISTORY_PARENT_NOT_IMPORTED` ให้หยุดและส่งเฉพาะผลสรุป/รหัสข้อผิดพลาด ไม่แก้ snapshot ไม่แก้ receipt และไม่ส่งออก/นำเข้าผล MOU ซ้ำเอง ถ้าพบ `SSH_HOST_KEY_REQUIRES_OWNER_CHECK` อย่าปิดการตรวจ host key

## ลิงก์หลักฐาน — ตรวจเฉพาะ snapshot ในเครื่อง

นับจาก snapshot ผล MOU ที่นำเข้าแล้ว โดยไม่เรียกเครือข่าย:

| รายการ | จำนวน |
| --- | ---: |
| ผลประเมิน | 1,353 |
| รายการที่มีลิงก์ | 1,314 |
| URL ไม่ซ้ำตามข้อความตรงตัว | 625 |
| HTTPS ที่ drive.google.com | 1,068 |
| HTTPS ที่ docs.google.com | 191 |
| HTTPS โดเมนอื่น | 54 |
| HTTP ที่ต้องตรวจเพิ่มเติม | 1 |
| ธงไฟล์แนบเดิมใน snapshot | 0 |

ยอดตามโดเมนเป็นจำนวนรายการอ้างอิง ไม่ใช่จำนวนไฟล์ ลิงก์ซ้ำไม่ใช่เหตุให้ลบข้อมูล และธงไฟล์ 0 ไม่ได้แปลว่าไม่มีไฟล์อยู่ปลายทาง ลิงก์ยังไม่ได้ตรวจการเปิด/เจ้าของ/สิทธิ์/เนื้อหา/อายุ จึงยังรับรองความพร้อมหลักฐานไม่ได้ ไม่เปลี่ยน HTTP เป็น HTTPS อัตโนมัติ และไม่เปลี่ยนสิทธิ์ไฟล์เป็นสาธารณะ

## หลังได้รับผลส่งออก

1. ตรวจ snapshot ประวัติและความสอดคล้องกับผลที่นำเข้าแล้ว หากมีความต่างให้สรุปก่อนดำเนินการ
2. ตรวจบัญชีเจ้าของ ทรัพยากร private หัวตาราง รูปแบบเซลล์ และพื้นที่ว่างใน `mou_review_history` แบบสดก่อนนำเข้า ห้ามทับแถวที่มีข้อมูลหรือ replay ช่วงที่ตรวจผ่านแล้ว
3. นำเข้าเป็นข้อความ literal และตัวเลขตาม schema พร้อม checkpoint และอ่านกลับเทียบทุกเซลล์ โดยไม่แก้ `mou_progress`, users หรือ identities
4. วางแผนตรวจสิทธิ์หลักฐานอย่างจำกัดขอบเขตกับเจ้าของข้อมูล แยกจากการคัดลอกไฟล์/เปลี่ยนสิทธิ์ และทดสอบหน้าประวัติเฉพาะ admin
5. จากนั้นจึงเตรียมการบันทึก/ส่งประเมิน/อนุมัติ รวมการป้องกันเขียนชน การสำรองและ rollback ก่อน GitHub/Vercel — ยังไม่ cutover ระบบเดิม
