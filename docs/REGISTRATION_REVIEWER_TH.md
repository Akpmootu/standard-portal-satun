## อัปเดต Google Apps Script (ทำก่อน restart เว็บด้วยโค้ดใหม่)
1. ในโครงการ Standard Portal MOU Writer เดิม ตั้ง Script Property MOU_WRITES_ENABLED เป็น 0 แล้วบันทึก รอคำขอเดิมจบก่อนเริ่มอัปเดต
2. แทน Code.gs/Writer.gs เดิมด้วย Writer.gs ในชุดนี้ทั้งหมด อย่าเพิ่มสำเนาซ้ำในอีกไฟล์ โค้ดใหม่ใช้ signed protocol v2 และรองรับการลงทะเบียน ไม่มี secret อยู่ในไฟล์นี้
3. เพิ่มไฟล์สคริปต์ SetupRegistration แล้ววาง SetupRegistration.gs จากชุดนี้
4. บันทึกและเลือกฟังก์ชัน setupRegistrationTables แล้ว Run จะสร้างเฉพาะตารางว่าง reviewer_profiles และ registration_requests ใน Application Data เดิม ไม่เปลี่ยนผู้ใช้ บทบาท หรือผลประเมิน หากมีตารางแล้วจะตรวจหัวตารางและไม่เขียนทับ
5. Run checkRegistrationSetup ต้องได้ PASS: 12 tables readable
6. Deploy > Manage deployments > เลือก Web app เดิม > Edit > Version: New version > Deploy ใช้ URL /exec เดิม สิทธิ์ OAuth และการแชร์ชีตยังเหมือนเดิม ไม่ต้องสร้างกุญแจใหม่
7. ปิดเซิร์ฟเวอร์เดิมด้วย Ctrl+C ใน PowerShell แล้วรันคำสั่งด้านล่าง จากนั้นตั้ง Script Property MOU_WRITES_ENABLED กลับเป็น 1 เมื่อ deployment อัปเดตแล้ว

```powershell
Set-Location -LiteralPath 'C:\Users\user\Documents\Codex\2026-09-01\new-chat\work\standard-portal-google'
$portalNode = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe'
$env:MOU_WRITES_ENABLED = '1'
& $portalNode --env-file-if-exists=.env.local src/server.js
```

8. เปิด http://127.0.0.1:3000/ เข้าสู่ระบบใหม่แล้วทดสอบด้วยใบสมัครจริงที่ต้องการใช้งาน การอนุมัติแอดมินให้สิทธิ์จัดการบัญชีและตรวจทุกหน่วยบริการ ให้แอดมินผู้รับผิดชอบตรวจตัวตนก่อนเลือก

ต้องอัปเดตทั้ง Apps Script และ Node พร้อมกัน โค้ดคนละรุ่นจะปฏิเสธคำขอ ไม่ควรเปิดรับผู้ใช้ระหว่างอัปเดต หากมีปัญหาให้ตั้ง gate Google กลับเป็น 0 และตรวจผลคำขอ/receipt ก่อนส่งใหม่ โดยเฉพาะ COMMIT_UNCERTAIN ห้ามเปลี่ยน request ID เพื่อบันทึกซ้ำ

## ผลตรวจและข้อจำกัด
- ทดสอบสมัคร อนุมัติ ปฏิเสธ ขอบเขตผู้ตรวจ การถอนสิทธิ์ CSRF และการปลอมชื่อ/บทบาท รวมถึง Apps Script bundle ที่เขียนแต่ละธุรกรรมด้วย batch เดียวภายใต้ ScriptLock
- ทดสอบผ่านหน้าเว็บด้วยบัญชีสมมติ: สมัคร → แอดมินอนุมัติ reviewer → ผู้สมัครเห็นอนุมัติ → หน้าตรวจผูกชื่อจากโปรไฟล์
- ยังไม่ได้มอบบทบาทให้บัญชีจริงในรอบนี้ และยังไม่ทดสอบ deployment ใหม่กับข้อมูลจริง
- การปฏิเสธคำขอยังไม่เปิดให้ผู้สมัครส่งใหม่หรือแก้ใบสมัครเดิมผ่าน UI ต้องให้แอดมินตรวจคำขอที่ปฏิเสธก่อน
- ขอบเขตผู้ตรวจที่เพิ่มในรอบนี้เป็น MOU และปีงบประมาณเท่านั้น CTAM/HAIT จะย้าย workflow ในขั้นต่อไป
- ยังไม่เปิดเว็บไซต์สาธารณะหรือย้ายข้อมูลทั้งระบบจาก PHP/MySQL; token Google ของผู้ใช้ใหม่ต้องผ่านการอนุญาตของ OAuth project เดิม หาก project อยู่ Testing ผู้ใช้ต้องอยู่ในรายชื่อทดสอบของเจ้าของก่อน
