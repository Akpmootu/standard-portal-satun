# แก้ไขตามผลตรวจ 8 ประเด็น

## ขั้นที่ 1 — ลดการชนโควตา Google Sheets

- รวม table reads ที่รอพร้อมกันเป็น values:batchGet ครั้งละไม่เกิน 12 ตาราง ตรวจ schema/ขอบเขตเดิมทุกตาราง
- อ่านข้อมูลสิทธิ์สามตารางในชุดเดียว ข้อมูลนี้ใช้ซ้ำได้เฉพาะภายใน HTTP request เดียว ไม่เก็บสิทธิ์/บัญชี/ผลประเมินข้าม request การปิดบัญชีมีผลใน request ถัดไป
- หน้าภาพรวม รายงาน กราฟสาธารณะ ประวัติ และรายงาน integrations เตรียมชุดอ่านที่ทราบแน่นอนก่อนใช้ ลด waterfall; บัญชีผู้ตรวจยังไม่อ่าน CTAM/HAIT ผ่านหน้าภาพรวม
- แคชเฉพาะสารบบหน่วยบริการที่ตรวจแล้ว id/name/type 5 นาที คืนสำเนา ไม่เก็บรายชื่อบุคคลหรือข้อมูลคอลัมน์อื่น และไม่คืนข้อมูลหมดอายุเมื่อ refresh ล้มเหลว
- เมื่อ Google ตอบ 429 ไม่ retry ทันที พักอย่างน้อย 60 วินาทีและเคารพ Retry-After แบบมีขอบเขต 120 วินาที; transient 5xx ใช้ backoff พร้อม jitter
- มีงบอ่านใน process เดียว 45 ครั้งต่อ rolling minute เพื่อเหลือ headroom โดยยังคงข้อผิดพลาดแบบ fail closed; ส่ง Retry-After ให้ client รู้เวลาที่ควรรอ
- diagnostic ตรวจตารางทั้งหมดเปลี่ยนเป็น bounded batches เช่นกัน ไม่อ่าน metadata ใหม่ทุกตาราง

### หลักฐานทดสอบ

ทดสอบแบบ red → green สำหรับการรวม reads/cache/429/Retry-After และการรวมชุด overview/integrations จากนั้นทดสอบทั้งชุด 199 รายการผ่าน พร้อม source/config check และ build Writer ผ่าน

ในแบบจำลอง overview รวมการอ่าน access tables ใช้ไม่เกิน 6 คำขอเมื่อสารบบยังไม่อยู่ในแคช และ 3 คำขอเมื่อสารบบพร้อม เทียบ baseline audit 15 คำขอ (ลด 60% / 80%) ตรวจการเปลี่ยน identity เป็น disabled แล้วถูกปฏิเสธใน request ถัดไปด้วย

### ขอบเขตที่ต้องเข้าใจ

งบอ่านและ cooldown ใช้ร่วมภายใน process ของแอป ไม่ใช่ distributed rate limit ที่รับรองทั้ง Vercel ทุก instance และไม่ครอบคลุมการใช้ Google โดยเครื่องมืออื่นทั้งหมด Google ยังบังคับโควตาระดับ owner/project อยู่ จึงยังต้องตรวจ concurrent usage ใน staging ก่อนระบุจำนวนผู้ใช้ที่รองรับ ไม่เพิ่ม subscription หรือเปิดบริการเก็บข้อมูลใหม่

แคชสารบบอาจแสดงชื่อหน่วยบริการเก่าได้ไม่เกิน 5 นาที แต่ไม่ใช้แคชนี้เก็บ role หรืออนุมัติสิทธิ์ การเปลี่ยน schema/จำนวนแถวในชีตยังตรวจจาก metadata ปัจจุบันต่อ request ส่วนการเขียนยังใช้ Writer ตรวจสิทธิ์ปัจจุบันซ้ำและ expectedVersion ตามเดิม

การเผยแพร่ขั้นนี้แก้ฝั่ง Node จึงไม่ต้องเปลี่ยน Apps Script ออนไลน์ ชุด Writer ที่ build ใหม่ต่างเฉพาะ helper อ่านที่ไม่เปลี่ยนกติกาการเขียน เก็บไว้ให้ source สอดคล้องกัน

## ขั้นที่ 3 — เสร็จด้านโค้ดและการตรวจในชุดจำลอง

ตัวช่วยเซสชันเตือนก่อนหมดอายุ เก็บร่างในแท็บ และกู้ CSRF จากการเข้าสู่บัญชีเดิมเท่านั้น ไม่ต่ออายุ cookie หรือเพิ่มสิทธิ์ ไม่ส่งคำขอเขียนซ้ำอัตโนมัติ รายละเอียดและข้อจำกัดใน SESSION_RECOVERY_TH.md ชุดทดสอบรวม 215 ผ่าน ขั้นถัดไปคือขั้นที่ 4 ตามลำดับเดิม

## ขั้นที่ 4 — ส่งคำขอลงทะเบียนใหม่

รองรับแก้ไขข้อมูลในคำขอ rejected ด้วยบัญชี Google เดิมและ expectedVersion ตรงกัน ส่งกลับ pending โดยไม่เพิ่มสิทธิ์ เก็บ snapshot ก่อน/หลังใน audit_log เดิม และแสดงประวัติแก่เจ้าของคำขอ/แอดมิน คำขอ pending หรือ approved ส่งใหม่ไม่ได้ ดูแผนและหลักฐาน tests ใน REGISTRATION_RESUBMISSION_PLAN_TH.md ขั้นถัดไปคือขั้นที่ 5 หน้าแสดงข้อผิดพลาด HTML

## ขั้นที่ 5 — หน้าข้อผิดพลาด

GET/HEAD ที่ขอ HTML ได้หน้า error ภาษาไทยตาม status พร้อมทางไปต่อ API/mutation คง JSON ไม่แสดง stack/query/provider error มี explicit GET retry พร้อม Retry-After และไม่มี retry อัตโนมัติ ใช้ CSS ในหน้าและ CSP hash ที่ normalize line endings ตรวจ 229 tests และ browser responsive แล้ว ดู ERROR_PAGES_PLAN_TH.md ขั้นถัดไปคือขั้นที่ 6 frozen dependency lockfile

## ขั้นที่ 6 — Frozen dependencies

ใช้ pnpm11.25.0 และ Node24.x, CI ใช้ frozen-lockfile/ignore-scripts ตาม pnpm-lock.yaml เดิม กำหนด packageManager กับ pnpm-workspace.yaml ให้ Vercel ใช้รุ่นเดียวกันและบังคับ frozen/ignoreScripts ตรวจ clean install และ manifestไม่ตรงlockถูกปฏิเสธจริง พร้อม tests229รายการจากชุดติดตั้งแยกผ่าน ตรวจ Transitions เดิมควบคู่โดยไม่เพิ่มUIที่ไม่เกี่ยวกับงาน ดู FROZEN_INSTALL_TH.md ขั้นต่อไปคือขั้นที่7 ความจุตารางและ retention

## ขั้นที่ 7 — ความจุและ retention
