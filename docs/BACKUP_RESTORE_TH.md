# สำรองและกู้คืน Standard Portal

ผลทดสอบ 9 ตุลาคม 2569: สำรองข้อมูล 25 ตาราง 2,344 แถว พร้อมไฟล์ PDF 6,480,625 ไบต์ไว้ในไฟล์ AES-256-GCM; กู้คืนลง Google Sheets แยกและอ่านกลับเทียบ 33,874 เซลล์ผ่าน ไฟล์ PDF กู้จากข้อมูลสำรองเข้าโฟลเดอร์ Drive ใหม่ ตรวจขนาดและ SHA-256 ผ่าน และแก้เฉพาะ manifest ในชีตทดสอบให้อ้างไฟล์ที่กู้คืนแล้ว

ชีตทดสอบชื่อ `Standard Portal — Isolated Restore Test — 2026-10-09` เป็นส่วนตัวของ dh.satun@gmail.com ไม่เชื่อมกับเว็บหรือ writer จริง การทดสอบไม่เปลี่ยนผลประเมินในระบบใช้งาน

## การสำรอง

เรียก `node scripts/backup-portal.js` จากโฟลเดอร์โครงการบนเครื่องเจ้าของที่ตั้งค่าแล้ว สคริปต์อ่านตารางสองครั้งและต้องตรงกันก่อนรับ snapshot ดาวน์โหลดไฟล์ complete ทุกไฟล์ ตรวจ SHA-256 แล้วเข้ารหัส ตรวจถอดรหัสซ้ำก่อนรายงานสำเร็จ หากเกินขีดจำกัดข้อมูลหรือไฟล์รวม 100 MB จะหยุดและแจ้งข้อผิดพลาด ไม่มีการละทิ้งไฟล์เงียบ ๆ

ไฟล์เข้ารหัสอยู่ใน `.backups/` ส่วนกุญแจอยู่ใน `.secrets/backup-key.json` ซึ่งห้ามส่งเข้า GitHub, Vercel หรือแชท ต้องเก็บสำเนากุญแจในที่ปลอดภัยแยกจากสำเนาข้อมูล จัดผู้รับผิดชอบและรอบสำรองก่อนสลับระบบจริง ขณะนี้เป็นการสำรองด้วยมือ ยังไม่มีตารางสำรองอัตโนมัติหรือสำเนานอกเครื่อง

ตรวจความสมบูรณ์ด้วย `node scripts/backup-portal.js --verify <ไฟล์เข้ารหัส>` หากกุญแจผิด ข้อมูลถูกแก้ หรือไฟล์แนบไม่ครบ ต้องไม่ใช้ชุดนั้นกู้คืน

## การกู้คืนและย้อนกลับ

1. ระงับการเขียนในระบบใหม่ที่ gate ของเว็บและ writer ก่อนกู้ระบบจริง แล้วสำรองสถานะล่าสุดไว้ ห้ามเปิดสองระบบให้เขียนพร้อมกันระหว่างสลับ
2. สร้างชีตส่วนตัวแยกจากแม่แบบที่ตรวจแล้ว คงชื่อแท็บ หัวตาราง ประเภทเซลล์ รูปแบบ และโครงสร้างเดิม ตรวจสิทธิ์ owner-only ก่อนนำข้อมูลเข้า
3. ถอดรหัสด้วยกุญแจสำรอง ตรวจ source ID/schema/ID ซ้ำ/ไฟล์ครบก่อนเขียน `scripts/restore-backup-plan.js` ส่งออกได้ครั้งละไม่เกิน 100 แถวโดยไม่พิมพ์กุญแจหรือเนื้อหาไฟล์แนบ ใช้ Sheets API เขียนค่า literal ในขอบเขตที่อ่านตรวจไว้ แล้วอ่านกลับเทียบทุกเซลล์ ล้างแถวส่วนเกินเฉพาะเป้าหมายกู้คืนที่ได้รับการยืนยัน
4. `scripts/restore-backup-files.js <ไฟล์เข้ารหัส>` สร้างโฟลเดอร์ทดสอบใหม่และกู้ไฟล์ complete จาก bytes ในข้อมูลสำรอง ตรวจ checksum และความเป็นส่วนตัว ส่งคืน mapping รหัส Drive เดิม/ใหม่ใน receipt ส่วนตัว ต้องแก้ `files.drive_file_id` ในชีตที่กู้คืนตาม mapping ไม่ใช้รหัสจากไฟล์เก่าโดยไม่ตรวจ
5. ตรวจรายชื่อหน่วยบริการจาก directory ในชุดสำรองเทียบ reference sheet คง reference sheet/รูปแบบแม่แบบสำรองไว้ด้วย ข้อมูลสำรองนี้เก็บค่าตารางและ directory ไม่ใช่ภาพ/สูตร/รูปแบบทั้งหมดของ Google Sheets
6. ทดสอบ Google Login, บทบาท, รอบประเมิน, รายงาน, ไฟล์หลักฐาน และ CAS ในระบบแยกก่อนอนุมัติเปลี่ยนปลายทางจริง source ID ของแอปและ writer ผูกตายตัว ต้องเปลี่ยนให้ตรงกันทั้งสองฝั่งและเผยแพร่รุ่นที่ผ่านทดสอบ ห้ามเปลี่ยนเฉพาะ environment แล้วอ้างว่าสลับสำเร็จ
7. หากต้องย้อนกลับ ให้ปิดการเขียนรุ่นใหม่ เก็บธุรกรรมหลังสลับสำหรับกระทบยอด และคืนรุ่นแอป/ข้อมูลที่ตรวจแล้วร่วมกัน การย้อนโค้ดอย่างเดียวไม่ย้อนข้อมูล Sheets ไม่เปิดระบบเดิมให้เขียนจนกำหนดเจ้าของข้อมูลหลักและกระทบยอดครบ
