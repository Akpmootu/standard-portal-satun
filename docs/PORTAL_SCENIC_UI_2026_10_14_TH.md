# UI ภายในตามคอนเซปต์หน้าแรก — 14 ตุลาคม 2569

ใช้โทนขาว เขียวเข้ม ภาพวิวสตูล และโลโก้ใบไม้ชุดเดียวกันผ่าน layout ส่วนกลาง ครอบคลุมบัญชี ภาพรวม Dashboard MOU/CTAM/HAIT ฟอร์มบันทึกและตรวจ ประวัติ รายงาน คู่มือ ประกาศ แจ้งเตือน สมัครใช้งาน ผู้ดูแล ข้อมูลย้อนหลัง และหน้าสถานะบริการ ไม่เพิ่ม framework หรือบริการภายนอก

## การใช้งานที่ปรับ

- เพิ่มค้นหาในรายการที่โหลดมาแล้วภายในสิทธิ์ พร้อมยอดพบและล้างคำค้น ไม่อ้างว่าค้นครบ archive ทุกหน้า
- เปิด/ย่อรายละเอียดทั้งหมด และปุ่มพิมพ์/บันทึก PDF ในรายงานด้วยหน้าพิมพ์ของเบราว์เซอร์
- ฟอร์มสิทธิ์แสดงขอบเขตหน่วยบริการ/ผู้ตรวจตามบทบาทที่เลือก ชื่อปุ่มระบุการกระทำ
- ส่งสมัคร/พิจารณาสำเร็จมีทางเปิดสถานะล่าสุด Telegram มีทางเปิดประวัติล่าสุดและยังไม่เปิดปุ่มส่งซ้ำเมื่อผลไม่แน่นอน
- ข้อผิดพลาดอัปโหลดแยกไม่เลือกไฟล์ ชนิดไฟล์ และขนาดเกินกำหนด
- ปุ่มที่ถูกล็อกจากสิทธิ์ รอบประเมิน หรือบริการยังคงถูกล็อก พร้อมเหตุผล ไม่เปิด Mistral
- ฟอนต์และภาพจากเว็บไซต์เอง ใช้ CSP เฉพาะ self ไม่มี inline script หรือ CDN ใหม่

## หลักฐานตรวจ

ตรวจ Chrome ผ่าน UI บน server 127.0.0.1:3008 ที่แยกโดยสิ้นเชิง ใช้ข้อมูลสมมติและแผนบันทึกจริงของแอป เก็บข้อมูลในหน่วยความจำ ไม่เชื่อม Google/Telegram

- เปิดเมนูภายในครบ 16 รายการ รวม archive (ตัวอ่าน fixture แก้โครงสร้างให้ตรง model ก่อนตรวจซ้ำ)
- ค้นหาหน่วยบริการ ลดเหลือ 1 รายการ ค้นไม่พบแสดง 0 และล้างคืนรายการ เปิด/ย่อ MOU ได้ 2 ข้อ
- บันทึก MOU, CTAM, HAIT สำเร็จใน fixture ส่งสมัครแล้วเปิดสถานะรออนุมัติได้
- บันทึกประกาศ ส่งความเห็น/คำตอบ HAIT ทำเครื่องหมายแจ้งเตือนอ่านแล้ว และช่องบทบาทผู้ตรวจเปลี่ยนตามเลือกผ่าน
- เลือกข้อมูลย้อนหลังผ่าน GET และตัวอย่าง Telegram รายสัปดาห์เปลี่ยนตาม query โดยไม่กดส่ง
- ดาวน์โหลด CSV ผ่านเบราว์เซอร์สำเร็จ
- ไม่พบล้นแนวนอนในเมนูหลักที่ตรวจที่ 320 px และหน้าสถานะบริการที่ 320/390/767/1024/1440 px; ตรวจเมนูมือถือและหน้าลงทะเบียน/HAIT ที่ 390 px
- ชุดทดสอบ 179 รายการผ่าน รวมวงจรสมัคร–อนุมัติ–บันทึก–ส่งกลับ–ส่งใหม่–ตรวจ และการปฏิเสธนอกสิทธิ์ ปรับการทดสอบ XSS ให้ยอมรับเฉพาะ script ส่วนกลางที่ระบุแน่นอน ยังปฏิเสธ script/HTML จากชีต

ไม่ได้ส่ง Telegram หรืออัปโหลดไฟล์จริงเพื่อทดสอบ UI ไม่แก้ผลประเมินหรือสิทธิ์บัญชี production ไม่ถือว่าปุ่มที่ถูกปิดตามกติกาเป็นปุ่มเสีย หน้าพิมพ์ขึ้นกับเบราว์เซอร์ ไม่ได้ตรวจเครื่องพิมพ์จริงหรือทุกอุปกรณ์ทุกขนาด

ขั้นต่อไป: ให้ผู้ใช้แต่ละบทบาททดลองงานประจำบนเว็บจริงและแจ้งจุดที่ต้องปรับ โดยงานตรวจ scheduler และเงื่อนไขโฮสต์ยังแยกจากการตรวจ UI
