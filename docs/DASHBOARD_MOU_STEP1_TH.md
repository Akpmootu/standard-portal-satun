# ขั้นที่ 1 — Dashboard และ MOU รูปแบบใหม่

อัปเดต 4 กันยายน 2026 · สถานะ: ต้นแบบ UI ที่กดใช้งานได้ด้วยข้อมูลจำลอง ยังไม่ใช่ระบบย้ายเสร็จหรือพร้อมใช้งานจริง

หมายเหตุอัปเดตขั้นที่ 2: `/dashboard` และ `/mou` เปลี่ยนเป็นหน้าอ่านจาก Sheets แล้ว รายละเอียดใน [คู่มือขั้นที่ 2](MOU_READ_STEP2_TH.md) ส่วน `/demo/dashboard` และ `/demo/mou` ยังคงเป็นหน้าทดลองตามเอกสารนี้

## เปิดทดลอง

จากโฟลเดอร์ `work/standard-portal-google`:

```powershell
& 'C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' scripts/preview-ui.js
```

- Dashboard: http://127.0.0.1:3001/demo/dashboard
- MOU: http://127.0.0.1:3001/demo/mou
- หรือ `npm run preview:ui` / `pnpm preview:ui` ถ้าติดตั้งไว้แล้ว
- หากพอร์ต 3001 ถูกใช้อยู่ ไม่ต้องหยุดโปรแกรมอื่น ใช้ `$env:DEMO_PORT = '3002'` ก่อนรัน แล้วเปิดพอร์ต 3002 แทน
- ตัว preview ไม่อ่านไฟล์ credentials ไม่ออกเครือข่ายไป Google รับเฉพาะ loopback บนเครื่องนี้
- แอปปกติหลัง restart มี `/dashboard` และ `/mou` สำหรับบัญชีที่ล็อกอินและอนุมัติแล้ว ปัจจุบันเปลี่ยนเป็นอ่านข้อมูลจาก Sheets ในขั้นที่ 2 ส่วนข้อมูลจำลองแยกที่ `/demo/*`

## สิ่งที่ส่งมอบ

- ธีมน้ำเงินเข้ม–เขียวอมฟ้า สอดคล้องกันทั้งสองหน้า พร้อม layout มือถือ เมนูย่อ และ focus สำหรับคีย์บอร์ด
- Dashboard: สรุปจำนวนข้อ ผ่านเกณฑ์ งานค้าง ความคืบหน้ารายหมวด รายชื่อหน่วยบริการที่ค้นหาได้ และลิงก์เปิดข้อที่ต้องแก้ไข
- ประเมิน MOU: เลือกหน่วยบริการและปี เลือกหมวด กรองรายการ เปิดรายละเอียดข้อ เลือกสถานะ กรอกคำอธิบายและลิงก์หลักฐาน จำลองบันทึก/แก้ไข/ยกเลิก
- ข้อที่ล็อกกดอ่านได้และอธิบายเหตุผล ไม่ทำให้เข้าใจผิดว่าปุ่มเสีย
- เตือนก่อนทิ้งแบบร่าง ตรวจข้อมูลจำเป็นและลิงก์ HTTP(S) ปฏิเสธ `javascript:`, `data:`, URL ที่ฝัง username/password และข้อมูลยาวเกินกำหนด
- บันทึกจำลองเปลี่ยนผลตรวจเป็นรอตรวจสอบและอัปเดต Dashboard ในหน้าเดียวกัน การรีเฟรช/เปิดแท็บใหม่จะกลับชุดตัวอย่างเริ่มต้น
- แบบร่างอยู่เฉพาะหน่วยความจำ ไม่ใช้ localStorage, sessionStorage หรือส่งผลประเมินไป API; CSP ปิด `connect-src` และ `form-action` ของหน้าต้นแบบ

ข้อมูลจำลองมี 4 ประเภทหน่วยบริการและหัวข้อตัวอย่างแบบย่อ 17 ข้อ ไม่ใช่ชื่อ/ข้อความ/จำนวนตัวชี้วัดครบชุดจากฐานข้อมูลเดิม ปีอื่นไม่มีผลประเมินตัวอย่าง ห้ามนำจำนวนหรือเปอร์เซ็นต์นี้ไปอ้างเป็นผลประเมินจริง

## ขั้นตอนเดิมที่รักษาไว้

ตรวจจากสำเนาโค้ด `../hait-rg12-site/mou_assessment.php` และ `../hait-rg12-site/api_mou_save.php` เทียบกับภาพที่ผู้ใช้ส่ง ไม่แก้ไฟล์เดิมหรือ production

| ขั้นเดิม | ต้นแบบใหม่ |
| --- | --- |
| เลือกหน่วยบริการ + ปี | แถบตัวเลือกด้านบน แสดงประเภทของหน่วยบริการและปี |
| เลือก 6 หมวด | Tab ที่ใช้คีย์บอร์ดลูกศรได้; โรงพยาบาลไม่แสดงหมวด 6 |
| เปิดข้อประเมิน | การ์ดพับ/ขยาย; แม้ล็อกก็อ่านผลและเหตุผลได้ |
| เลือกผล | มี/ผ่านเกณฑ์, กำลังดำเนินการ, ไม่มี/ไม่ผ่านเกณฑ์ |
| กรอกรายละเอียด + ลิงก์หลักฐาน | บังคับทั้งสองช่องเหมือนเดิม; ไม่เพิ่มขั้น upload ที่แบบเดิมยังไม่มี |
| บันทึก | ขั้นนี้ใช้ “จำลองบันทึกผล” เท่านั้น |
| ดูผลตรวจ / แก้ไขใหม่ | แสดงตรวจแล้ว/รอตรวจ/ต้องแก้ไข พร้อมตัวอย่างความเห็น; แก้ไขแล้วกลับรอตรวจ |

ไม่มีการบังคับส่งทั้งหมวดเป็น wizard ใหม่ เพราะระบบเดิมบันทึกเป็นรายข้อ

## กฎล็อกที่นำมาทดสอบ

- DHO: เปิดประเมินหมวด 1, 3, 5; PCU: หมวด 1, 3, 4, 5, 6; PHO: ทุกหมวด
- โรงพยาบาลไม่แสดงหมวด 6 และข้อ 5.1–5.6 อ้างอิงการประเมิน CTAM+
- DHO/PCU ไม่ประเมิน 3.1; PCU ไม่ประเมิน 4.1/4.2
- ประเมินได้เฉพาะปีงบประมาณปัจจุบัน โดยเปลี่ยนปีที่ 1 ตุลาคมตามเวลาไทย
- รอบ 6 เดือนและรอบ 9/12 เดือนอิงสวิตช์ตั้งค่า ไม่ตัดสินจากเดือนปัจจุบันเพียงอย่างเดียว; รอบ 12 เดือนใช้สวิตช์เดียวกับ 9/12 ตามเดิม
- ชุดทดลองเริ่มด้วยปิดรอบ 6 เดือนและเปิดรอบ 9/12; เปิด “ตั้งค่าเงื่อนไขรอบประเมินจำลอง” เพื่อทดลองเปลี่ยนได้
- เปอร์เซ็นต์ยังใช้จำนวนข้อที่แสดงเป็นตัวหาร รวมข้อที่ล็อกตามวิธีนับหน้าเดิม จึงไม่ใช่เปอร์เซ็นต์เฉพาะข้อที่ต้องประเมิน

**ประเด็นต้องยืนยันก่อนเชื่อมบันทึกจริง:** หน้า PHP เดิมล็อกตามประเภท/รอบ แม้ดูด้วย admin แต่ save API เดิมยกเว้นให้ admin กฎสองจุดไม่ตรงกัน ต้นแบบยึดพฤติกรรมหน้าประเมินเดิมก่อน ต้องสรุปสิทธิ์ admin และบังคับกฎเดียวกันบน server ก่อนเปิด writes ไม่ใช้กฎใน browser เป็นระบบอนุญาตจริง

## ผลตรวจในขั้นนี้

- Node unit/HTTP tests 39 รายการผ่าน; ตรวจ syntax ของ source, browser modules และ configuration ผ่าน
- ทดลองในเบราว์เซอร์: Dashboard → ข้อที่ต้องแก้ไข → แก้สถานะ/รายละเอียด/หลักฐาน → บันทึก → ตัวเลขเปลี่ยน 5/17 เป็น 6/17 → กลับ Dashboard ได้
- ลิงก์ผิดรูปแบบถูกปฏิเสธ; ข้อที่ล็อกเปิดอ่านได้; ปีเก่าล็อก; Hospital ซ่อนหมวด 6 และระบุ CTAM+
- ค้นหาไม่พบแสดง empty state; ยกเลิก/เตือนแบบร่าง; รีเฟรชกลับข้อมูลเริ่มต้น
- ตรวจภาพเดสก์ท็อปและมือถือ 390px; ไม่พบ JavaScript error ระหว่าง flow ที่ทดสอบ
- ไม่ได้ทดสอบกับ Google writes, real uploads, concurrent production load หรือบัญชีของผู้ใช้จริงหลายราย

## ขั้นถัดไปจนย้ายระบบ

1. **ตรวจรับต้นแบบนี้:** ตรวจการจัดหน้าและขั้นตอน ประกอบกับรายการตัวชี้วัดเดิมฉบับเต็ม รวมกรณี admin ที่ต้องตัดสินให้ชัด
2. **เชื่อมข้อมูลอ่านจริง:** นำรายการหน่วยบริการ/หมวด/ตัวชี้วัด/รอบประเมินที่ยืนยันแล้วมาใช้แทน fixtures แสดง MOU จาก Sheets ตามบัญชีและหน่วยบริการที่อนุมัติ ตรวจจำนวน/รหัส/ปีให้ตรงของเดิมก่อน
3. **บันทึกและหลักฐานจริง:** หลังยืนยัน scopes ที่จำเป็น จัดทำ API ตรวจสิทธิ์/validation ฝั่ง server, ป้องกันเขียนทับพร้อมกันและบันทึกซ้ำ, ประวัติแก้ไข/ตรวจอนุมัติ, ไฟล์ Drive แบบ private พร้อมควบคุมการดาวน์โหลดและขนาดไฟล์
4. **ย้ายโมดูลที่เหลือ:** CTAM, HAIT, Smart Hospital และงานผู้ดูแล/รายงาน/แจ้งเตือนตาม inventory; LINE Login ทำเมื่อสรุปว่าจะใช้ร่วมกับ Google และออกแบบการผูกบัญชีแล้ว
5. **GitHub + ระบบทดสอบออนไลน์:** สร้าง repository private ตรวจ secrets/ไฟล์ข้อมูลก่อน commit และ push ตั้ง automated tests; ตรวจเงื่อนไขแผน Vercel ก่อน deploy preview ตั้ง production OAuth/redirect/secret environment แยก staging และ production ไม่มีการเปิด Billing อัตโนมัติ
6. **ย้ายข้อมูลและเปิดจริง:** สำรองข้อมูลเดิม ทดลองย้ายชุดเล็ก ตรวจจำนวน/ศูนย์นำหน้า/เจ้าของ/ไฟล์/ประวัติ ทดสอบสิทธิ์ข้ามหน่วยบริการและโหลดพร้อมกัน จัดแผน freeze, cutover, backup/restore และ rollback แล้วจึงเปลี่ยน URL ใช้งานจริง

Vercel/GitHub ยังไม่ได้ deploy/push ในขั้นนี้ แผนฟรีไม่ได้แปลว่าใช้ได้กับทุกลักษณะองค์กรหรือไม่มี quota ต้องตรวจข้อกำหนด hosting, อายุ OAuth token, พื้นที่ Drive และ Sheets API ก่อนตัดสินใจเปิดจริง
